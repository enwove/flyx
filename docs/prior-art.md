## 2. Algorithmic and Architectural References

### Per-model sampling defaults

- llama.cpp reads `general.sampling.*` from GGUF when initializing its sampler. [Model sampler initialization](https://github.com/ggml-org/llama.cpp/blob/3cadf644b73227331a55bd80b0959ca6a13fc775/common/common.cpp#L1079-L1137)
- vLLM loads Hugging Face generation configuration and supports operator overrides. SGLang's `--sampling-defaults model` uses the checkpoint's sampling parameters. [vLLM engine arguments](https://docs.vllm.ai/en/stable/configuration/engine_args/#--generation-config) · [SGLang sampling parameters](https://github.com/sgl-project/sglang/blob/2800baa29705614c459de217df489b11d13da70b/docs/docs/basic_usage/sampling_params.mdx)
- LM Studio supports per-model inference defaults and named presets that bundle generation settings. [Per-model defaults](https://lmstudio.ai/docs/app/advanced/per-model) · [Config presets](https://lmstudio.ai/docs/app/presets)

### Models and Speculative Drafters
- **Qwen3.5 / Qwen3** (Qwen team): target architectures; float64 reference (`python/reference/flyx_ref/target.py`) verified against HuggingFace `transformers`.
- **MiniCPM5** (OpenBMB, `openbmb/MiniCPM5-1B`, Apache-2.0): a Llama, the attention without q/k norms; the tiny Llama's golden tokens and `tests/e2e/check_real_model.py` compare with `transformers`' modeling code; its `tokenizer.json` states the pre-tokenizer (numbers in groups of three, then a Qwen2-like split) that `core/tokenizer` writes by hand; its chat template is a test fixture (`tests/core/render/templates/`). `llama.cpp`'s converter is why a Llama GGUF is refused: it reorders a Llama's q and k rows for its interleaved rotary pairs.
- **DV** (bifill-dv, the research code DV comes from, and an earlier internal CUDA port of DV): a canvas of N MASK slots after the anchor run by the target's base weights plus a rank-256 LoRA adapter with its own norms, a learned MASK embedding and a residual context (the slot's previous top-16 expected embedding); a bilinear path selector over each slot's top 16 (DFlash2-style); trees grown as a beam per depth (DYN, EAGLE-2-style) or taken from a fixed pool of rank tuples that leave the selector's best path once (ST); exact tree verification; and the target's own LoRA (LoRA: Hu et al., *"LoRA: Low-Rank Adaptation of Large Language Models"*, 2021; V-LoRA: bifill-dv's `raft.py` `WithLoRA`, rank 64 beside each of a layer's seven linears, unmerged, no scale, run on every row of the target and never on the canvas's). `python/reference/flyx_ref/dv.py` follows bifill-dv's `evalgen.py` mode DV from its design and math, held to bifill-dv's own functions (`tests/python/reference/check_dv_bifill.py`); `ops/draft/ref.h` and `ops/canvas/ref.h` are its pieces in float64. The converter (`python/convert/export_dv.py`, `flyx_convert --dv`) is ported from the earlier CUDA port's (its exports read the same, byte for byte), `models/dv.h` follows its description in what it holds on flyx's own blocks and rounds, and the CUDA kernels (`backends/cuda/kernels/dv.cu`) take their design from its kernels (the pool tree scored depth by depth in one block, the selector's token tables built once, the canvas slid on the device). The canvas pass's grouped GEMMs (a base weight with its adapter's `a`, the adapters' `b` side by side) run on flyx's own multi-tile kernel. GSM8K (Cobbe et al., *"Training Verifiers to Solve Math Word Problems"*, 2021; `openai/grade-school-math`, MIT) as bifill-dv prompts and scores it (its answer extraction and accuracy rule, and its count of forwards an answer needs) is what `tests/e2e/check_dv.py` holds DV to.
- **LoRA Adapters**: Hu et al. (*"LoRA: Low-Rank Adaptation of Large Language Models"*, 2021), Kalajdzievski (*"A Rank Stabilization Scaling Factor for Fine-Tuning with LoRA"*, 2023: rsLoRA's alpha / sqrt(r)); Hugging Face PEFT's adapter folder (`adapter_config.json`, `adapter_model.safetensors`, its tensor names) and `LoraConfig`'s fields that `--lora` refuses (DoRA, aLoRA's invocation tokens, PiSSA / OLoRA / CorDA / LoftQ initializations that change the base); the Hub's `base_model:adapter:` relation for the adapters made for a model; Punica (Chen et al., 2023) and S-LoRA (Sheng et al., 2023) for unmerged adapters' shrink and expand products beside the base GEMM; `llama.cpp`'s `--lora` for adapters run at their stored precision (the comparison in [numerics](design/numerics.md)).
- **DFlash / DFlash2** (z-lab, *"Block Diffusion for Flash Speculative Decoding"*; `vllm-project/speculators` MIT definition): block drafting conditioned on target hidden taps, grouped dynamic causal convolutions, low-rank candidate selector, vLLM inference-time tap/anchor layout, and `llama.cpp`'s GGUF layout for the drafter (`general.architecture=dflash` keys and tensor names). Inco AI's DFlash 2 drafter for Inkling-2 (`incoai/Inkling-2-Mini-DFlash2`, Apache-2.0; its `sglang_inkling_dflash2.py`): the selector's soft cap applied after the pair's correction (`selector_softcap_mode`), candidates taken from the real vocabulary of a padded head, and features that count the target's hidden states and end at its final norm's output, the capture DSpark's ids go to. DFlash itself (z-lab's `DFlashDraftModel`, e.g. `z-lab/Qwen3-8B-DFlash-b16`) runs as DFlash2's block without the convolutions and selector, read against the math of z-lab's published `dflash.py` (none of its code is used).
- **Inkling-2 & DSpark** (Thinking Machines, `thinkingmachines/Inkling-2-Mini`; Unsloth GGUF & `llama.cpp` `inkling2_loop` target layout and Markov DSpark companion layout (`general.architecture=dflash`, `has_markov_context=true`)): looped core transformer with cross-pass low-rank loop gates, Block Attention Residuals depth-wise mixing, causal depthwise ShortConv with per-head dynamic taps on global layers, relative-position-bias attention with per-query sink and logarithmic position scaling, sparse MoE with SiTU activation and per-expert NVFP4 tensor scales, and the companion DSpark 3-layer block-uniform drafter with a Markov RNN refinement head.
- **DSpark** (Cheng et al., *"DSpark: Confidence-Scheduled Speculative Decoding with Semi-Autoregressive Generation"*, 2026; DeepSeek's `DeepSpec`, MIT, and its released checkpoints): the block drafter whose every row drafts, the vanilla Markov head (a rank-256 bias from the previous token, walked left to right), read from DeepSpec's `Qwen3DSparkModel` checkpoints. `python/reference/flyx_ref/draft.py` follows its modeling and evaluation code from their description and is held to it (each row's hidden state, walk score and draft: `tests/python/reference/check_dspark_deepspec.py`, run by hand against a DeepSpec checkout); no DeepSpec code is copied.
- **DSpine** (Zhang et al., *"Draft in Parallel, Condition Through Depth: Adjacent Causal Injection for Speculative Decoding"*, 2026; Tencent's `tencent/Qwen3-8B-DSpine-b16` and `tencent/Qwen3.8-27B-DSpine-b16`, Apache-2.0): DFlash's block drafting with causal attention inside the block, a code bridge after every layer that passes a gated low-rank message from each position to the next, and the last write redone with the drafted token's code to choose among the head's top 16. `python/reference/flyx_ref/dspine.py` and `ops/dspine/ref.h` are written from the paper and the released checkpoints' configs, read against the math of the authors' SGLang plugin and MLX port (`Tencent/DSpine` at `d037a9b`, `sglang_dspine/` and `dspine_mlx/`, Apache-2.0; none of their code is used); the walk's every-sender scores and their chain are flyx's own kernels (`backends/cuda/kernels/dspine.cu`).
- **EAGLE-4** (EAGLE-4 Team, *"EAGLE-4: One Flexible Drafter for All Batch Sizes and Hardware"*, 2026; EAGLE-Corp's `EAGLE-Corp/Qwen3.8-27B-EAGLE4`, its `LlamaForCausalLMEagle4` and the EAGLE-4 code it was released with, source-available; after Li et al., *"EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty"*, 2024, *"EAGLE-2"*, 2024, and *"EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test"*, 2025): one Llama layer over the normed embedding beside the normed hidden, the hidden a projection of several of the target's layers (each tap normed on its own), each step after the first continuing from the normed output, and a low-rank head that picks the candidates its own head scores. `python/reference/flyx_ref/eagle4.py`, the cpu_ref backend and the CUDA regions are written from the released config and weights and from the math of its modeling code (none of its code or tuned settings is used); the trees are EAGLE-2's (a beam a step, every scored candidate a node, the best by path log-probability verified), grown by flyx's own kernels (`backends/cuda/kernels/eagle4.cu`), and SGLang's EAGLE-4 worker (`--speculative-algorithm EAGLE_HARNESS` with 12 steps, top 4, 16 tokens) is what [benchmarks](benchmarks.md) section 7 compares with.
- **Coupled drafts under sampling**: Daliri, Musco and Suresh (*"Coupling without Communication and Drafter-Invariant Speculative Decoding"*, 2024): a drafter and the target sampling with the same Gumbel noise, so their choices agree as often as their distributions do. flyx's sampler is already Gumbel-max keyed on (seed, position, token) (`ops/sampling/sampling.h`); block drafters walk their candidates by `coupled_draft_score` with that noise, MTP's draft is the sampler's choice on its head's best logits (`draft_choice`: the reply's penalties, the filters and that noise), and the output stays the plain sampler's.
- **Prompt Lookup & Suffix Decoding**: Saxena (*"Prompt Lookup Decoding"*, 2023), `llama.cpp` lookup, Oliaro et al. (*"SuffixDecoding"*, 2024), LZ77 overlapping copy semantics, and `YASAKANI` (`yasakani-dev/yasakani`) for the copy cursor with local re-anchoring past an edit and wide copy verification passes gated by full-acceptance runs with time-based back-off.
- **Speculative Trees**: Miao et al. (*"SpecInfer"*, 2023), Cai et al. (*"Medusa"*, 2024, typical acceptance), Li et al. (*"EAGLE-2"*, 2024, best-first dynamic tree), Chen et al. (*"Sequoia"*, 2024, cost-budgeted trees), Nguyen et al. (*"Turning Up the Heat"*, 2024, min-p), and hybrid tree analyses (STree, TreeWY, Bole, LumoTree).

### Kernels, Quantization, and Attention
- **GGUF & GGML Quants**: [GGUF specification](https://github.com/ggml-org/ggml/blob/master/docs/gguf.md), `llama.cpp` metadata/tensor naming and K-quant/IQ block definitions (I. Kawrakow and ggml authors), packed block GEMMs (`mmvq`, `mmq`, `dp4a`, `get_int_from_table_16`), host-resident input embeddings, and `llama.cpp`'s precision floor (`fattn-mma-f16`, `fattn-vec`, split-bf16 chunked GDN `gated-delta-net-mma.cu`, FP4 prefill on Blackwell).
- **Stream-K & Parallel Reductions**: Osama et al. (*"Stream-K: Work-centric Parallel Decomposition for Dense Matrix Multiplication on the GPU"*, 2023) and CUDA `threadFenceReduction` counter-and-fence pattern (adapted with shape-fixed K partitions for bitwise invariance).
- **Small-Row Tensor-Core Block GEMMs**: `YASAKANI` (`yasakani-dev/yasakani`) for lane-ordered weight loads and warp-split K reductions without shared memory (adapted to GGML blocks with fixed 32-stream trees).
- **FlashAttention & Chunked GDN**: Dao (*"FlashAttention-2"*, 2023), GQA head packing (FlashAttention-3 / FlashInfer), SageAttention2 (Zhang et al., 2024, for the finding that Ada `sm_89` `mma.f32.e4m3.e4m3.f32` accumulates in 22 bits rather than float32—motivating our binary16 tensor-core path for `rows_attention_q=fp8` on `sm_89`), Yang et al. (*"Parallelizing Linear Transformers with the Delta Rule over Sequence Length"*, NeurIPS 2024; *"Gated Delta Networks"*, ICLR 2025).
- **Tiered KV & Sparse/Low-Bit Attention**: `llama.cpp` `--no-kv-offload`, FlexGen (Sheng et al., 2023), vLLM swap space, LMCache, SGLang HiCache, Quest (Tang et al., 2024), InfiniGen (Lee et al., 2024), ShadowKV (Sun et al., 2024), StrataFlux (2026), and NVIDIA CUDA Virtual Memory Management APIs.

### Runtime, Serving, Chat, and Tooling
- **Engine & Loop Design**: `llama.cpp` loadable backends (`GGML_BACKEND_DL`), context checkpoints, `test-backend-ops`, and pinned prefetch loader; `vLLM` / `ExLlamaV2` / `MLC-LLM` single-loop stepped execution; `velox-inferer` Profile/Backend/Variant split; `lithos-metal` token ring.
- **Chat Templates & Grammars**: `llama.cpp` template format detection and input special-token marking; Ollama / vLLM / SGLang Jinja-verified native renderers; XGrammar structural tags; `llama.cpp` optimistic post-sample grammar checking (extended to full speculative rounds); OpenAI Responses API & SDK item/event schemas.
- **Thinking Budget**: SGLang's thinking-budget logit processor, TensorRT-LLM's `thinking_token_budget` and the vLLM thinking-budget logits processors (NVIDIA NeMo's, and the community `vllm-thinking-budget`): count the reply's thinking tokens and, once the budget is spent, allow only the next token of the closing marker (TensorRT-LLM's guard against a second marker). flyx takes the markers from the chat format and the model's tokenizer (SGLang issue #25536: fixed ids that did not match Qwen3.6) and holds the budget as its grammars are held (`core/exec/thinking_budget.h`). Design only, no code.
- **Hub, Monitor & Build**: `llama.cpp` `-hf org/name:quant` syntax; `huggingface_hub` cache layout and env vars; `hf_transfer` multi-range downloads; FIPS 180-4 SHA-256; `Strata` (`Niko1221/Strata`) terminal monitor, telemetry snapshot, and conversation snapshot distinction; `Basalt` (`jesdga95/basalt`) built-in server status page; `sccache` / `GGML_CCACHE` auto-detection.
